# fixtures/api — выгрузка API сайта переводов

Здесь лежат ответы API **ровно в том виде, в котором их отдаёт сервер**, по
одному файлу на страницу:

```
entries.all.page-1.json     ответ GET /entries?page=1
entries.all.page-2.json     ответ GET /entries?page=2
glossary.page-1.json        ответ GET /glossary?page=1
_meta.json                  служебное: когда и откуда выгружали
```

Структура файлов описана единственной схемой —
[tools/sources/api/contract.ts](../../tools/sources/api/contract.ts). Через неё
проходят и живой HTTP-ответ, и эти файлы, поэтому выгрузка не может незаметно
разойтись с контрактом: расхождение падает при чтении.

## Пока API нет

`PF2E_RU_API_MODE=fixture` (значение по умолчанию) — сборка читает эти файлы и
в сеть не ходит. Пополняйте их руками; главное — не забывать про `meta`:

- `meta.total` — сколько записей всего;
- страницы читаются, пока `page * perPage < total`, поэтому обещанная в `meta`
  страница обязана существовать, иначе сборка честно упадёт.

## Когда API появится

```bash
PF2E_RU_API_MODE=http PF2E_RU_API_BASE_URL=https://… npm run pull:api
```

Команда перезапишет эти же файлы, удалит лишние страницы и обновит `_meta.json`.
В `npm run build` при этом не меняется ничего.

Файлы коммитятся: так сборка остаётся воспроизводимой и офлайновой, а дифф
показывает, что именно поменялось на стороне переводчиков.
